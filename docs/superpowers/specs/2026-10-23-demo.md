# Demo class: proteger un formulario

Diseño aprobado en la conversación: demostrar registros automatizados, explicar el recorrido del formulario, introducir un límite, repetir la misma prueba y cerrar con verificación de correos como próximo tema. Duración objetivo: 4:40; límite: 5:00.

Decisiones de implementación: Node.js 22+, módulos nativos, HTML/CSS/JS sin dependencias ni servicios. Solo escucha en 127.0.0.1. Formulario y lista de registros visibles a la vez. Script de doce solicitudes secuenciales, exclusivamente a la instancia local. Ventana fija por cliente de cinco solicitudes / treinta segundos, por IP real del socket. Cambiar de escena vacía registros, métricas y contadores. El control de escenas requiere un token local; no forma parte del formulario ni de la solución de producción.

Alternativas: desplegar con Redis añadiría configuración innecesaria para grabar hoy; una simulación visual no demostraría HTTP real. Se implementa un servidor real con memoria local y se documenta su alcance didáctico. El usuario autorizó crear el repositorio y construir la demo; no se requiere otra aprobación para ejecutar este diseño.

Entregables: repositorio Git local, interfaz, servidor, limitador legible, script de envíos, comandos de escenas, pruebas y guion en español. No se promete que el límite valide leads, detenga un DDoS ni asegure toda la app.
